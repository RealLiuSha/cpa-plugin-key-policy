# V5 交付目标

用户已批准：稳健、交互友好、可持续维护；不二开 CPA，不以临时补丁完成。

## 范围与规则

- 认证仍负责额度拦截，对外沿用 CPA 通用 401；删除宿主不消费的 Rejection 输出，保留内部业务原因。
- 每个 Key 独立维护日、7 天、30 天额度周期。自然日按 usage_timezone 计算。手动重置立即清零选中周期，下次为当天零点加 1/7/30 天；自动重置按原到期边界推进。
- 额度状态与历史消费分离。重置保留历史与其他周期；日重置同时恢复该 Key 的模型日额度。
- 模型 billing_multiplier 默认 1，仅作用于 Token 模型的输入、输出、缓存读写扣费金额。实际 Token 不变；免费及按次计费不变；导入基础价格不覆盖倍率。
- Key 页面优先展示用户名称、额度剩余、准确重置日期；统一服务端状态，明确区分全部额度受限和部分模型受限；桌面和移动端均完成验收。

## 迁移与恢复

- 读取 schema v3/v4，写入 v5。旧周期已用额按迁移时原滚动窗口承接；新的首期到期为迁移日期加 7/30 天，日额度仍次日到期。
- 已有历史数据、Key 哈希、权限、限额、模型价格及引用不丢失。不得用 updated_at 推测历史重置时间。
- 替换前保存完整旧 state/usage 备份；先持久化已迁移的 usage，再写 state。中途失败可按已持久化周期继续，不能重建周期或重复结转。
- 回退必须恢复与旧插件匹配的成对数据；恢复旧快照会舍弃升级后新消费，不自动回退运行中的数据。
- 线上目录仅只读。原始样本保存在任务临时目录，不加入仓库。

2. 重构列表、重置流程、详情与模型价格交互。
3. 验证真实 v4 样本迁移、重载幂等、独立重置、失败恢复、计费一致；运行现有相关检查并进行桌面/移动端浏览器验收。
4. 更新文档、嵌入页面和交付证据。保留未部署的明确边界，不 commit/push。
